# Tutorial 3: Patching Existing Files

Sometimes you don't want to *create* new files — you want to modify files
that already exist in the target project.  Scaffoldix patches let you insert,
replace, or append content to existing files using explicit markers or
content-matching strategies.

---

## How patches work

Every patch carries an `idempotencyKey`.  On the first run Scaffoldix inserts
a stamp (`SCAFFOLDIX_PATCH:<key>`) into the file and applies the change.  On
subsequent runs the stamp is detected and the patch is **skipped** — so you
can safely re-run generation without duplicating content.

---

## Patch operations

### `marker_insert` — insert inside a region

Inserts content **after** `markerStart` and **before** `markerEnd`:

```yaml
patches:
  - kind: marker_insert
    file: src/app.ts
    idempotencyKey: register-user-module
    markerStart: "// <SCAFFOLDIX:START:modules>"
    markerEnd: "// <SCAFFOLDIX:END:modules>"
    contentTemplate: 'import { UserModule } from "./modules/user";'
```

**Target file before:**

```typescript
// <SCAFFOLDIX:START:modules>
// <SCAFFOLDIX:END:modules>
```

**After:**

```typescript
// <SCAFFOLDIX:START:modules>
import { UserModule } from "./modules/user"; // SCAFFOLDIX_PATCH:register-user-module
// <SCAFFOLDIX:END:modules>
```

### `marker_replace` — replace a region

Replaces everything between the markers with new content:

```yaml
patches:
  - kind: marker_replace
    file: src/config.ts
    idempotencyKey: set-db-url
    markerStart: "// <SCAFFOLDIX:START:dbConfig>"
    markerEnd: "// <SCAFFOLDIX:END:dbConfig>"
    contentTemplate: 'const DB_URL = "{{dbUrl}}";'
```

### `append_if_missing` — append if content not already present

Appends content to the end of a file if it isn't already there:

```yaml
patches:
  - kind: append_if_missing
    file: .gitignore
    idempotencyKey: ignore-dist
    contentTemplate: |
      # Generated by Scaffoldix
      dist/
      .scaffoldix/
```

### `regex_replace` — replace content matching a pattern

```yaml
patches:
  - kind: regex_replace
    file: package.json
    idempotencyKey: bump-node-version
    pattern: '"node": ">=[0-9.]+"'
    replacement: '"node": ">=18"'
```

### `json_merge` — deep-merge JSON

```yaml
patches:
  - kind: json_merge
    file: package.json
    idempotencyKey: add-scripts
    content: |
      {
        "scripts": {
          "generate": "scaffoldix generate"
        }
      }
```

### `yaml_merge` — deep-merge YAML

```yaml
patches:
  - kind: yaml_merge
    file: .github/workflows/ci.yml
    idempotencyKey: add-test-step
    content: |
      jobs:
        test:
          steps:
            - run: pnpm test
```

## Using templates from files

Instead of inline `contentTemplate`, load content from a file in the pack:

```yaml
patches:
  - kind: marker_insert
    file: src/routes.ts
    idempotencyKey: add-user-route
    markerStart: "// <ROUTES:START>"
    markerEnd: "// <ROUTES:END>"
    path: patches/user-route.hbs      # relative to pack root
```

`patches/user-route.hbs`:
```handlebars
router.use("/{{entityNameKebabCase}}", {{entityName}}Router);
```

---

## Controlling patch order

Use the `order` field (lower = first) to control execution order when the
natural manifest order isn't sufficient:

```yaml
patches:
  - kind: marker_insert
    file: src/index.ts
    idempotencyKey: step-2
    order: 20
    contentTemplate: "// Step 2"

  - kind: append_if_missing
    file: src/index.ts
    idempotencyKey: step-1
    order: 10
    contentTemplate: "// Step 1"
```

Patches without an `order` field run after all ordered patches (treated as `Infinity`).

---

## Skipping patches during development

Use `--skip-patches` to apply only templates without running any patches:

```bash
scaffoldix generate my-pack:service --skip-patches
```
